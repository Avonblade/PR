# База данных «Фитнес-учёт»

Скрипт `Database/01_CreateAndSeed.sql` создаёт базу `PR19_Fitness`. Начальные записи используют вымышленные контактные данные. Даты абонементов и расписание рассчитываются относительно даты установки.

| Таблица | Назначение |
| --- | --- |
| `Employees` | Сотрудники, роли, логины и хеши паролей. Тренировки и групповые посещения ссылаются на тренера |
| `Clients` | ФИО, дата рождения, контакты, уникальный номер карты и статус |
| `Memberships` | Тип, сроки, лимит, состояние и дата отмены. Остаток считается по посещениям, статус «Истёк» — по дате |
| `Freezes` | Периоды и причины заморозки. Одна незакрытая запись на абонемент |
| `Rooms` | Залы и их вместимость |
| `Trainings` | Зал, тренер, время, тип и день недели. Длительность вычисляется по времени начала и конца |
| `Bookings` | Запись клиента на конкретную дату занятия, доступ и отметка. Повторная запись на то же занятие запрещена |
| `Visits` | Вход, выход, тип доступа, стоимость разового входа. Групповое посещение связано с записью и тренером |

Составные внешние ключи проверяют, что абонемент и групповая запись принадлежат тому же клиенту. Уникальный индекс допускает только одно посещение на групповую запись. Изменения из WPF проходят в транзакциях с блокировкой записи на время проверки пересечений, лимитов и вместимости. Карточки клиентов, залы, тренировки и сотрудники используют `rowversion` для обнаружения устаревших данных.
